# Pet Store API Testing Project

A Postman-based API testing project for the [Swagger Pet Store API](https://petstore.swagger.io/), covering user registration, authentication, order management, and pet management endpoints with both positive and negative test scenarios.

## Overview

This project contains a Postman collection with **26 requests** and **181 test assertions**, organized into 4 functional areas. It uses Postman's built-in test scripts (`pm.test`) for assertions and dynamic variables, and can be run either interactively in Postman or headlessly via **Newman**, with results reported through **Allure**.

## What's tested

| Folder | Coverage |
|---|---|
| **Registration** | Creating single/multiple users, duplicate/invalid registration, fetching users by username (valid and non-existent), updating a user (valid and with a wrong username) |
| **Login and Logout** | Valid login, logout, invalid login with wrong password, invalid login with wrong username |
| **Pets orders** | Checking store inventory, creating an order, fetching an order by ID, fetching a non-existent order, deleting an order, confirming a deleted order is gone |
| **Pets management** | Adding a pet, fetching a pet by valid/invalid ID, filtering pets by status, updating a pet, deleting a pet, confirming a deleted pet is gone |

Each request includes assertions for things like status codes, response body structure, and field-level values, and several scenarios explicitly test negative/edge cases (invalid IDs, wrong credentials, already-deleted resources) rather than just the happy path.

## Project structure

```
├── Pets Store.postman_collection.json      # Main Postman collection (requests + tests)
├── test environment.postman_environment.json  # Environment variables (Base_URL, sessionToken)
├── newman/                                 # HTML report generated by Newman CLI runs
├── allure-report/                          # Allure HTML report
└── README.md
```

## Prerequisites

- [Postman](https://www.postman.com/downloads/) (for running/exploring the collection manually)
- [Node.js](https://nodejs.org/) (for running the collection from the command line)
- [Newman](https://www.npmjs.com/package/newman) — Postman's CLI runner:
  ```bash
  npm install -g newman
  ```
- (Optional) Allure command line, if you want to regenerate the Allure report:
  ```bash
  npm install -g allure-commandline
  ```

## How to run

### Option 1 — Postman (manual)

1. Open Postman and import `Pets Store.postman_collection.json`.
2. Import `test environment.postman_environment.json` and select it as the active environment.
3. Run individual requests, or use the **Collection Runner** to execute the whole suite.

### Option 2 — Newman (command line)

```bash
newman run "Pets Store.postman_collection.json" \
  -e "test environment.postman_environment.json" \
  --reporters cli,html \
  --reporter-html-export newman/report.html
```

### Option 3 — Allure report

```bash
newman run "Pets Store.postman_collection.json" \
  -e "test environment.postman_environment.json" \
  --reporters allure \
  --reporter-allure-export allure-results

allure generate allure-results --clean -o allure-report
allure open allure-report
```

## Environment variables

| Variable | Description |
|---|---|
| `Base_URL` | Base URL of the API under test (`petstore.swagger.io/v2`) |
| `sessionToken` | Session token used for authenticated requests |

## Notes

- This collection targets the public Swagger Pet Store demo API, so test data (pets, orders, users) is not persistent and may reset or behave inconsistently, since it's a shared public sandbox.
- Some requests rely on IDs created earlier in the run (e.g., a pet created in one request is fetched/updated/deleted in later requests), so the collection is designed to be run in order, either as a full run or folder by folder.
